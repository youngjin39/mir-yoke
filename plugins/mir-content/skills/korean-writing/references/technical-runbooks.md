# 기술 가이드와 운영 절차

Inspired by bear2u/natural-korean-skills at 2a4f1fc (ideas only, no license; wording original).

## 메모에서 초안으로

1. 따라 할 독자의 숙련도, 대상 버전과 실행 환경을 정합니다.
2. 메모를 확인된 사실, 해석, 미확정 항목으로 나눕니다. 누락된 정보를 문장으로
   채워 넣지 말고 확인 사항으로 남깁니다.
3. 사전 조건, 권한, 순서, 예상 결과, 확인 방법과 실패 시 복구 경로를 배치합니다.
4. 명령과 예시는 검증한 범위를 밝히고, 파괴적인 단계는 영향과 필요한 승인을 설명합니다.
5. 초안을 작성한 뒤 [문맥 검토](contextual-revision.md)로 의미와 말투를 점검합니다.

## 문서 종류에 따른 구성

운영 절차에는 위의 실행·확인·복구 흐름을 유지합니다. 다른 기술 문서는 독자가
찾는 답에 맞춰 다음과 같이 구성합니다.

- 설치 안내: 도달할 상태와 지원 환경을 밝히고, 준비 사항 → 설치·설정 →
  실행 확인 → 설치를 취소하는 방법으로 이어 갑니다.
- API/SDK 안내: 사용 범위와 인증을 먼저 설명한 뒤, 호출 예제 → 입력·출력 계약 →
  실패 응답과 재시도 판단 → 사용 한도와 보안상 주의점으로 이어 갑니다.
- ADR: 해결할 문제 → 검토한 선택지 → 채택한 판단과 근거 → 영향과 후속 조치 →
  결정을 다시 검토할 조건을 적습니다.
- 문제 해결 안내: 관찰한 증상과 원인 가설을 구분하고, 가설을 가릴 검사 →
  검사 결과에 맞는 조치 → 정상화 확인 → 같은 문제가 반복될 때의 대응을 적습니다.
- 마이그레이션: 변경 목적과 호환 범위 → 데이터 보존·작업 중단 계획 → 사전 검사 →
  전환 작업 → 결과 비교 → 이전 상태로 복원하는 조건과 방법을 적습니다.

## 완료 기준

독자가 단계별 성공 여부를 판별하고, 실패하면 중단하거나 복구할 수 있어야 합니다.
미확정 사실과 필요한 확인 사항이 보이고, 독자에게 없는 근거나 약속을 전달하지
않는지 검토합니다. 기준을 충족하지 못한 부분은 완료로 표시하지 않습니다.

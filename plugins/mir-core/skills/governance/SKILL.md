# Repository Governance

## Workflow

1. Locate the repository-local instruction source of truth and identify generated derivatives before
   proposing an edit.
2. Read the repository's identity, ownership, protected paths, permission boundaries, required
   checks, agent roles, hooks, and state only when those surfaces exist.
3. Separate binding local policy, generated projections, advisory observations, historical material,
   and host capabilities. Presence does not imply adoption or authority.
4. Classify findings as blocking contract violations, actionable drift, advisory improvements, or
   intentional local exceptions using the repository's own terms.
5. Change canonical sources first, regenerate derivatives with the repository-owned command, and
   preserve narrower path-scoped policy.
6. Verify instruction size, generated parity, registry uniqueness, hook executability, and every
   repository-declared gate with concrete evidence.
7. For a multi-repository request, inspect each repository under its own contract and produce
   target-specific findings or prompts. Observation never grants cross-repository write authority.

Do not assume a fleet topology, Mir CLI, bootstrap phase, memory store, provider marker, or global
registry. Use those concepts only when the current repository explicitly declares them.

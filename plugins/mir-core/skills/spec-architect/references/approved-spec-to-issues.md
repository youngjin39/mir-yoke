# Approved specification to issue drafts

Inspired by Q00/ouroboros at 825bc68.

This optional advisory recipe lets Main prepare reviewable issue drafts from an
approved specification. Approval of the specification is not publication authority.
Use available authorized tools; this reference bundles no issue-writing tool.

1. Pin the approved specification revision and exact destination, including the
   repository or tracker and project when relevant. Resolve an unknown destination
   before preparing destination-specific writes; do not infer it from tool access.
2. Map acceptance criteria into a parent issue describing the outcome and child
   issues describing bounded work, dependencies and verifiable completion. Preserve
   links to the originating criteria; do not invent requirements to fill a template.
3. Check the pinned destination for duplicates with available read authority.
   Reuse or link relevant issues in the draft plan. If the duplicate check is
   unavailable or inconclusive, disclose that limit rather than claiming uniqueness.
4. Show the exact writes before publication: destination, each title and body,
   parent/child relationships, criterion links, and any planned labels or updates.
   Make draft creation, existing-issue edits and publication distinct in the preview.
5. Obtain explicit authority for those writes before sending them to the external
   service. Main may rely on existing explicit authority covering the exact writes;
   revised scope or destination requires authority covering the revision. Without
   it, retain the reviewable drafts locally or in the conversation.
6. After an authorized write, inspect the resulting issue contents and links and
   report their locations. Report partial failures accurately before retrying;
   check for already-created issues to avoid duplicates.

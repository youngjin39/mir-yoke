# Phase 11 — Back-Propagation (Innovation Share-Back) — Historical Pointer

This phase specified a central hub that scanned managed repositories for new skills, hooks, agents, phase patterns and config fields, recorded each as a typed innovation with an identifier rule and a share status, suppressed false positives through a controlled skip vocabulary that could only change by review, and pushed every candidate through a four-way triage of share to fleet, absorb into the maintainer harness, promote straight to the template, or archive without sharing. It kept five named sync directions, including lateral repository-to-repository propagation, asserted central direct-apply authority over active repositories with holds only for sealed or excepted ones, and gave conflict-resolution rules for incompatible, abstractable and single-repository patterns. The drift detector and share dispatcher it depended on are not shipped here.

Authority for this repository now sits with ADR-83 (the product boundary: the four-file starter, the Project Agent Kit recipe, and the optional installed CLI are the only adoption layers), ADR-84 (upgrade guidance, which already classifies this whole directory as history), ADR-85 (agent contracts), ADR-86 (Mir Harness maintains this repository), and ADR-81 (the Starter). Fleet rollout, drift enforcement, central direct-apply, daemons and notifications are cancelled and are named here only to forbid their return. The current replacement guide is `docs/operations/harness-engineering-upgrade.md`.

A new session must not execute the historical procedure. The complete original is preserved in [the archive](../_archive/harness-engineering/phase-11-back-propagation-2026-05-23-historical.md).
